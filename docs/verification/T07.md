# T07 — Payment QR verification

Ticket: [#8](https://github.com/truongtoanr0602/EducationKeeptrack/issues/8). Review baseline: `7429c3bab29e216669bbb310d982975643eaf3a2`.

## Behavior checked

- Owner-scoped recipient persistence, input validation and stale recipient versions.
- Old debt 500,000 + new fees 900,000 − receipt 700,000 produces a QR request for exactly 700,000 VND; QR creation does not record a receipt.
- VietQR failure uses the owner's static PNG, then complete manual bank/account/name/amount/memo details when no image is available.
- Malformed PNG headers and compressed pixels, HTTP errors, interrupted streams and timeout failures use the fallback path. Invalid static uploads are rejected.
- Another teacher's class/student/recipient references cannot expose private QR data.
- A receipt or recipient change during generation discards the result; zero debt and missing recipient configuration return explicit validation errors. Changing the recipient without a replacement removes its old static QR.
- Desktop/mobile flows exercise recipient preview, all three QR modes, browser image failure switching to static QR, instructions for manual entry, and hiding a request when debt is reloaded.

## Additional checks

- Full API suite: `dotnet test EducationKeeptrack.slnx --logger 'console;verbosity=minimal'` with the local PostgreSQL test connection — 80 passed, 0 failed, 0 skipped.
- Full browser suite: `npx playwright test --workers=1` from `ui` with the isolated demo credentials — 16 passed across desktop and mobile.
- Release publication: `dotnet publish src/Host -c Release -o .local/t07-host --nologo` — passed.
- UI production build: `npm run build` from `ui` — passed.
- Real Kestrel upload of a valid 49,363-byte PNG — HTTP 200; verifies the recipient endpoint's body-size override.
- Live VietQR Quick Link smoke through the authenticated demo API — HTTP 200, `qrKind: vietqr`, amount `700000`. This checks provider integration, not account ownership or settlement in a banking app.
- Standards/spec reviews found malformed-image and interrupted-stream fallback gaps; both were fixed and reviewed again with no remaining actionable findings. The duplicate access-filter setup was an optional maintainability observation.

Recipient names are entered by the teacher and previewed as entered; no bank account-name lookup is implemented. Static images must correspond to the configured recipient, and the teacher must verify them. Source/account changes in another session are detected by five-second UI revalidation; verification failure hides the displayed QR. Scanning never confirms receipt of money.

## Standards

No documented standards or ADR breaches remain. The interrupted-response fallback issue was corrected and re-reviewed. Duplicate access-filter setup remains an optional maintainability observation, not a documented-standard violation.

## Spec

No actionable findings remain. PNG validation decodes bounded images; transport I/O failures use the fallback path; browser image failure tries the owner's static image before manual instructions. Malformed upload/image and transport failure scenarios have API coverage.

Final review: Standards — 0 unresolved actionable findings, 1 optional observation; Spec — 0 unresolved findings.
