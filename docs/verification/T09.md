# T09 — Receipt corrections

Ticket: [#10](https://github.com/truongtoanr0602/EducationKeeptrack/issues/10).
Review baseline: `86145a781c396b3a9241e93588c5f9624c524173`.

The approved test boundaries are authenticated system APIs with real PostgreSQL,
and browser behavior on desktop/mobile. Unrelated existing untracked files are
excluded from this implementation.

## Behavior

- Required reasons, preserved original receipts and immutable correction snapshots;
  replacement amounts, actual dates and notes are separate from correction timestamps.
- Cancellation across two periods reallocates remaining active receipts oldest debt
  first; cancelled/replaced receipts no longer contribute to balances.
- Previously unallocated money is not spent on later fees. Period holds retain as
  much backing as survives reversal, without guessing a receipt-level hold policy.
- Duplicate requests, stale versions, concurrent receipt/correction commands,
  ownership, CSRF and expired-service writes are checked through APIs.
- Failure after database save but before commit rolls back original status,
  replacement, allocations and version; the original key can retry safely.
- Transfer requests reject old versions; a durable versioned `receipt.corrected`
  event reaches the existing tuition-change contract for future PDF invalidation.
- Browser checks edit amount/date, mandatory reasons, lost-response retry,
  before/after history, cancellation, reload and mobile overflow.

PDF generation does not exist yet; this ticket supplies the durable change event,
rather than adding a reporting subsystem.

## Standards

No documented breaches or actionable bugs were found by the independent standards
review. One optional observation remains: allocation replay could move into a pure
domain operation if its policy grows; this ticket does not require that refactor.

## Spec

The independent spec review found one surplus-preservation defect: a date-only
replacement could spend the original receipt's unallocated credit on later fees.
Regression tests reproduced that defect and an equivalent held-money defect before
the fix. Replacement now carries existing unallocated credit (up to the corrected
amount) and retains historical backing for period holds. The implementer rechecked
the fix, including amount increases and decreases, against the ticket's prohibition
on implicitly spending surplus. No other requirements gaps were identified.

Final review: Standards — 0 actionable findings, 1 optional observation;
Spec — 1 finding corrected, 0 unresolved after implementer recheck.
